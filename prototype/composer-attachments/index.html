When files ride with a prompt

Picking a file starts its upload immediately, in parallel per file. The chip tracks progress; send never blocks on the picker. Try it above — toggle slow uploads to watch the states, and random failures for retry.

  1. Pick or paste → POST /v1/workspaces/{workspaceId}/attachments fires per file, in parallel. Server stores under .harold/attachments/ and appends that path to an existing .gitignore (skipped when none exists — never created).
  2. Chip shows upload progress → lime check when the descriptor lands. Failure shows retry (a fresh POST; ids are never reused).
  3. Removing a ready chip fires DELETE for its id. Removing mid-upload just cancels.
  4. Send: the client waits only for in-flight stragglers, then posts the prompt carrying { id, kind } references — bytes are never re-sent with the prompt.
  5. Server validates the agent's capabilities, resolves descriptors to workspace paths, and maps them to ACP content blocks in session/prompt.
  6. The user message renders optimistically in the transcript with thumbnails and file chips — mock-send above shows exactly this.

Upload timing — decision

Recommendation: start uploads at selection, not at send. Send waits only for in-flight stragglers, so the common case is an instant send. Progress is visible while the user keeps typing, and failures surface before the turn starts.

Upload-at-send — wait for each file, then send the prompt — also works and wastes nothing if the user backs out. But large files hold the turn hostage, send latency becomes unpredictable on slow links, and failures arrive at the worst moment. Uploaded-but-unsent files are cheap to reclaim either way: the client DELETEs on removal and a janitor sweep collects orphans on a TTL.

Workspace-scoped so it works before a session exists (first prompt creates the session). Files land under <workspace>/.harold/attachments/ so agents read them without additionalDirectories grants. On every upload the server checks the workspace root for a .gitignore: present → append .harold/attachments/ if missing (idempotent, no duplicates); absent → skip entirely. The server never creates a .gitignore.
